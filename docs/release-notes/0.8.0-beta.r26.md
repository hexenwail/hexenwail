### Changes from [0.8.0-beta.r25](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r25)

- Fixed every replacement texture in a gamedir being silently disabled by a config written before `0.8.0-beta.r17`. `r_texture_external` was a dead cvar defaulting to 0, and archived, so configs saved a meaningless `0` for months; the release that gave the cvar teeth turned all of those stale zeroes into "disable replacements here". A mission-pack install refused 202 of 202 replacement skins this way, falling back to embedded 8-bit skins — which on an `EF_SPECIAL_TRANS` model is a mottled translucent mess
  + The setting is now `r_external_textures` (default: 1). A new name is the only remedy that is not a heuristic, since an archived `0` cannot be told apart from a deliberate one
  + `r_texture_external` stays registered so old configs do not spew `Unknown command`, but it gates nothing, is never written back — so the stale line disappears the first time your config is rewritten — and its callback says what to set instead
  + The engine now says so when it declines a replacement because the gate is off, once per session. It previously refused an installed pack and printed nothing at all, which is what made this cost a session to find instead of one console line
- Added a demo playback bar, drawn during demo playback: a seek rail and cursor, the demo name, play/pause state, and the elapsed map time above the cursor. Reviewing a demo, or answering "where in the demo did this go wrong", was previously guesswork
  + Added `scr_demobar_timeout` cvar (default: 1), following Ironwail exactly — negative hides the bar, 0 pins it up for the whole demo, positive is the idle timeout in seconds. It fades over its last half second and re-arms on any keypress or pause
  + The cursor tracks the demo's file offset, not a time index, because a `.dem` header carries no duration. It therefore crawls through a quiet stretch and races through a busy one; that is the format, not a bug
- Added **HD Textures** and **Old Skin Alpha** rows to the Rendering submenu, for `r_external_textures` and `r_legacy_special_trans_alpha`. Both were reachable only from the console, and "HD Textures" is the one that spent seven months silently off on installs with a stale archived config. Both take effect on the next map load, and the menu says so while the cursor is on either row
- Changed the Water Alpha row to say that it reaches models only on map load. World water reads `r_wateralpha` every frame, so the slider is immediate there, but an `EF_TRANSPARENT` model bakes the value into its skin at upload and keeps whatever was current when it loaded. Of the 13 such models with an embedded skin across `data1`, Portals of Praevus, Storm over Thyrion, Wheel of Karma and Shadows of Chaos, 12 are affected — 22% of their skin texels on average, and effectively all of `stclrbm.mdl`. Invisible at the default of 1.0, so only a player who moves the slider ever saw it

This rolls up 17 commits since r25. Thirteen of those are merge commits, issue-tracker bookkeeping or documentation with no user-visible effect, and are omitted above.

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To turn it off**, launch with `-vanillaprogs`. The engine then ignores its own
  copy and uses whatever your Hexen II install provides. Nothing is deleted, so it
  is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it under `<userdir>/<gamedir>/` on Linux, which outranks the bundled copy.
  The engine prints `userdir is:` at startup if you are unsure which one you have;
  it is `~/.local/share/hexen2` on a fresh install and `~/.hexen2` if you already
  had one, and `-userdir` now overrides both. Windows has no user directory, so
  replace the files in `gamecode/` beside `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

One thing to know:

- **"Vanilla" now means two different things.** A build running our gamecode will
  behave differently from Raven's in ways that are not engine bugs. If you report
  a problem, please paste the `Gamecode:` line, or say whether `-vanillaprogs`
  changes what you see — that is the fastest way to tell whose bug it is, and it
  deletes nothing. This cuts both ways — some reports against older releases will
  have been gamecode issues we had already fixed.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.
