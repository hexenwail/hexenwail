Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out.

### Changes from [0.8.0-beta.r24](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r24)

- Fixed three separate ways a server could die, or corrupt memory, when a frame's entity updates outgrew the network datagram. Only the first is reachable in single player; the other two are why this release matters most to anyone hosting a game
  + Guarded the per-frame entity datagram, which had no size check at all. The first update that did not fit took the server down with `SZ_GetSpace: overflow without allowoverflow set` — on a listen server, the whole game
  + Fixed the per-frame datagram being built eight times larger than the wire accepts. A server that filled more than 4 KB of datagram did not fail to send it, it wrote up to 28 KB past a static buffer. The frames just after a client connects reach 4 KB on a dense map without trying
  + Added `sv_netsort` cvar (default: 1), deciding which entities survive a full datagram. Entities are costed into 256 distance-over-size priority bins and the worst bin that does not fit is dropped whole, so what you lose is the far-away clutter rather than whatever happened to be next in edict order. Set it to 0 for the old behaviour
- Fixed QC taking the engine to desktop through `sv.datagram`. Every mod-side `WriteByte`/`WriteCoord`/`WriteString` broadcast, plus `raineffect` and `particleexplosion`, wrote there with no bounds check, where the engine's own writers all tested first. An overflowing frame now drops that frame's broadcast effects instead of aborting
- Fixed sounds from every map you had played staying resident forever. The sound-name table was reset at startup and nowhere else, so a long enough playthrough walked it to the ceiling and died on `S_FindName: out of sfx_t` — the symptom Storm over Thyrion's own readme documents, along with the giveaway that relaunching clears it. A map change now releases what the next map does not need
- Fixed a repacked install being mounted correctly and then identified as nothing at all. Hexen II content was fingerprinted by the `.pak` container's CRC, which no `.pk3` can ever match, so converting `data1/pak0.pak` and `pak1.pak` to `.pk3` — the ~50% disk saving the feature exists for — made the engine refuse to start with "Unable to find a proper Hexen II installation" while its archives sat mounted two lines above. It now identifies content by what is inside the archive (requested by @Monolyth-42)
- Fixed a map failing to load with `Z_Malloc: failed on allocation`, hundreds of console lines after the thing that actually went wrong. Three allocations that scale with content were taken from the fixed 2 MB zone: the water T-junction heal (which is what killed `sot/egypt.bsp` at a hand-set low `gl_subdivide_size`), the archive directories, and the archive hash. A 64-file, 400-entry-each `.pk3` set alone was 1.9 MB of a 2 MB pool
- Capped what one deflated `.pk3` entry may inflate to, at 64 MB, refused at mount with a warning naming the archive. Deflate's ratio is unbounded and the only check was a 2 GB one, so a 261 KB archive could take peak memory from 296 MB to 558 MB with no diagnostic and no failure — it simply worked, expensively. `STORED` entries are exempt and still stream at no memory cost; the largest file Hexen II ships is 2.3 MB, so no plausible mod is affected
- Changed `r_legacy_special_trans_alpha` to default to 1, restoring pre-`3z3e` `EF_SPECIAL_TRANS` alpha semantics. That change moved the flag from a reversed blend function to the ordinary one, so a replacement skin's alpha silently went from meaning transparency to meaning opacity, and every skin authored against the older engine rendered inside out. Reported by BloodShot against his Vorpal Sword, whose alpha is 0 across 94.5% of its UV coverage
  + Measuring the corpus decided the default: every `EF_SPECIAL_TRANS` replacement skin on a retail `data1` plus Storm over Thyrion install is authored to the legacy convention and none to the current one, including SoT's own light shafts — third-party content broken by `3z3e` that nobody had connected to this bug
  + Set it to 0 if your skins are authored against the current convention. It is a switch rather than a heuristic because nothing in the file distinguishes the two: an all-zero channel is "fully opaque" under one reading and "fully invisible" under the other
- Fixed a declined skybox face drawing as a hole in the sky with no signal at all. `TexMgr_Init` was defined but never called, so the `notexture` and `nulltexture` placeholders never got a GL object and every consumer of them was inert. Both now upload Ironwail's 2x2 checkers, and a `.bsp` texture missing from the wad gets one too
- Added grayscale and 15/16-bit targa decoding, instead of declining those files. Types 3 and 11 at 8 or 16 bits, and 15/16-bit true colour on types 2 and 10. 16-bit grayscale is read as luminance8 + alpha8, matching FTE (confirmed by @Spoike); 16-bit true colour honours the top bit as alpha only when the header says the file carries one, since plenty of writers emit 16bpp with that field zero and obeying the bit unconditionally turns such an image fully transparent
- Fixed an unsupported-but-legal image killing the engine. `Image_LoadTGA` and `Image_LoadPCX` answered a header they could not decode with a fatal abort, so a texture pack shipping one variant took the whole engine down over a single face. Both now name the file, decline, and fall through to the next candidate — and declining a `.tga` no longer skips the perfectly good `.pcx` sitting next to it
- Added `external_vis` cvar (default: 1), loading a sidecar `.vis` "vispatch" file for unvised or badly-vised third-party maps. Supported by the GL client, its listen server, and the dedicated server — where broken vis mis-culls entities for every connected client rather than merely drawing wrongly for one. Any failure rolls back to the map's own vis rather than leaving patched data against original leafs
- Added `entsearch`, an entity search across `.map` sources, to the utilities. It answers "how is this property actually used, and where did Raven use it" by matching classname, property name and property value against three regular expressions, with `.pts` point files for stepping through hits in TrenchBroom. The config format is compatible with [Inky's MapSearch](http://earthday.free.fr/), which is the reference implementation and the one to use on Windows
- Added the sky wind authoring commands, closing the loop that previously meant editing `wind.cfg` by hand and reloading the map to look
  + `skywind [dist] [yaw] [period] [pitch]` prints or sets, live
  + `skywind_lookdir [period] [dist]` takes the direction from where you are looking, so you aim the camera the way you want the clouds to travel
  + `skywind_rotate <dyaw> [dpitch]`, `skywind_save` and `skywind_load`
  + Fixed `wind.cfg` pitch being parsed and discarded. Harmless while only reading, but a save would have silently zeroed the pitch of any file it round-tripped, quietly damaging cfgs authored for Ironwail
- Added the console commands a bug report needs, so a field report can arrive as text instead of as video
  + `apropos` / `find` — one substring search across commands, aliases *and* cvars, for when you do not know which of the three a setting lives in
  + `condump [name]` — console scrollback to a file
  + `gl_info` — driver vendor, renderer, version, GLSL and limits
  + `imagelist [prefix]` and `imagedump` — the live texture list, and every live texture out as a PNG beside your screenshots
  + `skies [prefix]`, `randmap [prefix]`, `maplist`'s sibling `games [prefix]` — what skyboxes, maps and gamedirs are actually installed
  + `tracepos`, `vid_describecurrentmode`, `gl_describetexturemodes`, `mapname`
  + `cycle` / `cycleback` / `inc` — step or increment a cvar; `resetall`, `resetcfg`, `writeconfig [name]`
- Added Ironwail's render toggles: `r_drawworld` (default: 1), `r_flatlightstyles` (default: 0; 1 holds each style at its mean, 2 at its peak), `r_oldskyleaf` (default: 0), `r_noshadow_list`, `r_simd` (default: 1) and `r_drawparticles` (default: 1)
  + `r_flatlightstyles` also flattens the torch-corona flicker, which has no upstream counterpart — someone who set the cvar to stop things flashing would not accept "except the torch flares"
  + `r_noshadow_list` excludes a model from `r_shadows` and ships a default curated from `data1`'s own progs: flames are the thing casting the light, and airborne projectiles have nothing under them
  + `r_aliasinfo` now prints `MOD_NOLERP` and `MOD_NOSHADOW`, so you can ask whether a list entry actually matched a loaded model
  + Named `r_drawparticles`, not upstream's `r_particles`, because ours is `gl_particles 0=square/1=round` and importing the name would leave two cvars disagreeing about what 0 means
- Added client cvars: `cl_confirmquit` (default: 1), `cl_screenshotname` (default: `shots/%map%_%date%_%time%`), `cl_gun_x`/`cl_gun_y`/`cl_gun_z` (default: 0) and `con_notifyfadetime` (default: 1)
  + `cl_confirmquit 0` is worth more than parity here: the prompt appears only when connected and not at the console, so a `quit` from a script, a bind or the command line silently opened a menu and left the engine running — exactly the case where nobody is there to answer it
  + `cl_screenshotname` expands `%map%`, `%date%` and `%time%` at capture, and creates the directory the template names
- Added `gl_cshiftpercent_contents`, `_damage`, `_bonus` and `_powerup` (default: 100), scaling each colour shift before they are combined. The existing `gl_cshiftpercent` is a master applied after, and both are wanted: killing the damage flash without losing the underwater tint is not something one global can express
- Added server cvars `max_edicts` (default: 8192), `sv_freezenonclients` (default: 0), `host_timescale` (default: 0 = off) and `sv_cheats` (default: 0, registered and never read, as upstream). `host_timescale` is the multiplier `host_framerate` is not — it does not couple world speed to frame rate
- Added `sv_gameplayfix_elevators` (default: 1) and `sv_gameplayfix_random` (default: 1), both archived and both revertible to the old behaviour
  + `sv_gameplayfix_elevators` lifts a rider by one epsilon when the platform carrying it blocks on it, which is the lift that stalls or stutters under its own passenger. 1 is clients only, 2 is all entities. Ironwail ships 2; this ships 1, because Hexen II leans on moving platforms far more than Quake does and its content is 1997-vintage, authored around the stall
  + `sv_gameplayfix_random` fixes `random()` being closed at both ends and following `RAND_MAX`, which is 31 bits on Linux and 15 on Windows. The common `floor(random() * n)` idiom therefore returned `n` itself — one past the end of whatever it was choosing from — once every 32768 calls on Windows and effectively never on Linux
- Added `snd_mixspeed` cvar (default: 44100) and the `-mixspeed` switch. The switch is how you actually set it: sound starts before `hexen.rc`, before `config.cfg` and before the command line is stuffed, so the cvar alone could never reach the device open in time
- Added `-userdir DIR`, the only way to redirect the user directory on Unix. The home directory comes from `getpwuid()` rather than `$HOME`, and an existing `~/.hexen2` deliberately beats the XDG location, so neither environment variable could move it. Used verbatim, with parent directories created
- Fixed the console being undismissable and untypeable after a savegame failed to load. `Couldn't load map` left input pointed at a game that did not exist, so the error filled the screen and no keystroke reached it. Reported by @Mathuzzz
- Fixed the Graphics submenu drawing its cursor on the wrong row. With a search filter active it sat one row too high for every item below a hidden one, and further off the more rows the filter hid
- Fixed a moving platform silently promoting itself to `SOLID_BSP`. Both pusher routines cleared the pusher's solid so a rider could pass, then restored a literal rather than what it actually was, and the change stuck for the rest of the map
- Reduced the pusher routines' stack use by 160 KB per call, moving their scratch arrays to static storage. That frame size is what blocks raising the edict ceiling, so this is groundwork rather than a change you will feel
- Updated libtimidity from mainstream, and made the MIDI backend reject SoundFont version 3 files and check the soundfont loaded before initialising
- Documented the server tick-rate contract for modders in `docs/MODDING_TICKRATE.md`. `sv_physfps` moved the tick from 20 Hz to 72 Hz in `0.8.0-beta.r16`, and the HexenC idiom `velocity = delta * 20` reads as a gain constant but is a hardcoded 1/frametime for the old tick — so it closed 100% of the gap per tick then and closes 28% now. The giveaway shape of a report of this kind is not "worse at 72" but "exact at 20". Found by BloodShot

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To turn it off**, launch with `-vanillaprogs`. The engine then ignores its own
  copy and uses whatever your Hexen II install provides. Nothing is deleted, so it
  is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it under `<userdir>/<gamedir>/` on Linux, which outranks the bundled copy.
  The engine prints `userdir is:` at startup if you are unsure which one you have;
  it is `~/.local/share/hexen2` on a fresh install and `~/.hexen2` if you already
  had one, and `-userdir` now overrides both. Windows has no user directory, so
  replace the files in `gamecode/` beside `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

One thing to know:

- **"Vanilla" now means two different things.** A build running our gamecode will
  behave differently from Raven's in ways that are not engine bugs. If you report
  a problem, please paste the `Gamecode:` line, or say whether `-vanillaprogs`
  changes what you see — that is the fastest way to tell whose bug it is, and it
  deletes nothing. This cuts both ways — some reports against older releases will
  have been gamecode issues we had already fixed.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.
