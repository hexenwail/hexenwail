Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out.

### Changes from [0.8.0-beta.r21](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r21)

❗ **Note**: there is no r22 download. The version was bumped for a maintenance re-tag that was never cut, so this release rolls up everything since r21.

- Rewrote the Mods menu to the standard the Quake engines set, developed against the [hexenworld.org](https://www.hexenworld.org/) add-on archive rather than against whatever happened to be on a dev box
  + Added a type-to-search filter matching both the display name and the directory name; Escape clears the filter, then leaves
  + Added readable display names from a shipped table, overridable per mod by a `modinfo.txt` in the mod directory, falling back to the directory name
  + Added an `[HW]` tag on HexenWorld mods, which are listed but not selectable — the Hexen II client cannot run `hwprogs.dat` gamecode
  + Added mouse hover selection, so clicking a row activates the row under the pointer instead of whatever the keyboard cursor sat on
  + Raised the mod limit to 256, and truncation now warns to console instead of silently dropping entries
  + Ellipsis-truncated over-long labels to the label column
- Fixed mod discovery missing seven of the thirty-nine mods in that archive. `FS_IsGamedir` recognised only `progs.dat`, `pak0-9.pak` and `*.pk3`; it now also accepts a loose `hwprogs.dat` or a `maps/` directory holding at least one `.bsp`. Those seven were launchable from the console the whole time — they were invisible to the mods menu and to `game` tab-completion only
- Added mods installed under the user directory. A mod dropped into `~/.hexen2/<mod>` was already fully playable but could not be found or selected anywhere; it is now listed in the mods menu, offered by `game` tab-completion, and accepted by `game <dir>`. A mod present under both roots merges into one entry, with the user directory's `modinfo.txt` winning the label
- Fixed a first-frame crash inside the NVIDIA driver on demo1 (Blackmarsh). An alias model carrying real indices but no pose data drew from a zero-sized buffer, so every vertex read past the end of it; such a mesh is now refused and draws as nothing. Mesa absorbed the read, which is why it reproduced only on NVIDIA
- Fixed dynamic lights disappearing on light-dense maps
  + Raised `MAX_DLIGHTS` from 32 to 128 and widened the per-surface light mask to match. Storm over Thyrion's meso peaks at 74 lights in a frame against the old pool of 32, so torches went permanently dark and which ones changed as you moved
  + Changed eviction, for the frames that still saturate: the engine now drops the light the eye sits furthest outside instead of always stomping the first slot, and a displaced light cannot return until the player has genuinely moved back toward it. Lights holding a slot within 600 units rose 24% over the previous release without the set thrashing
- Fixed `EF_TRANSPARENT` and `EF_SPECIAL_TRANS` models drawing fully opaque once a replacement texture pack was installed. Hexen II stores those models' translucency in palette indices, which an RGBA replacement has none of. The alpha is now rebuilt — but only where the pack expressed no transparency of its own, so a pack that shipped real alpha is left alone. Across `data1`, Portals and Storm over Thyrion this rewrites seven effect models and leaves forty-one untouched
- Fixed `EF_SPECIAL_TRANS` models compositing inverted under `r_oit 1`. Alpha is now stored as opacity rather than transparency, so order-independent transparency and the ordinary blend path agree. Six models set the flag — the four Eidolon endgame models and Storm over Thyrion's two ray models — and `r_oit` defaults to 0, which is why it went unreported
- Fixed the field of view on non-square pixel modes. The GL renderer sized the FOV to the pixel rectangle rather than to the shape of the picture, so a 320x200 mode displayed as 4:3 reported an effective FOV of 100.39 where it should read 90, and handed that overstated number to gamecode as well (thanks to @Spoike)
- Fixed `S_FindName: out of sfx_t` ending a long Storm over Thyrion playthrough. The sound name table never shrinks across map changes, so a run through enough maps exhausted it and died. Exhausting it now warns once and costs individual sounds rather than the session, and the table itself grew from 1024 entries to 4096 (288 KB against a 512 MB heap). The leak behind it is still open
- Fixed a `changelevel` landing between a client's prespawn and its spawn feeding that client the new map's signon list from the middle. Each buffer parses cleanly on its own, so there was no error — just baselines and static entities silently missing for the buffers that were skipped
- Changed an unknown server message from a silent one-byte skip to a hard error that says something useful: the offending byte, the previous message by name and length, and a hex+ASCII window around the failure. The old skip invented a payload for a message that does not exist, which guaranteed the stream stayed desynchronised and misapplied entity state for the rest of the packet
- Fixed runtime `game <dir>` killing a dedicated server outright with `Z_Malloc: Bad zone id 2`. The switch tore the filesystem down correctly and then died re-initialising a renderer the process never had
- Fixed piped console commands running together into one line on a dedicated server. `map demo1\nstatus\nquit\n` executed as the single command `map demo1statusquit`; a terminal delivers one line per frame so it never showed there
- Fixed the mods-menu scrollbar and footer stopping one row short of the list whenever the separator between fixed and scanned entries was on screen
- Added `vid_pixelaspect` cvar (default: 0 = auto), overriding the pixel aspect the engine derives from the video mode. Auto is 1.0 windowed, so existing setups render identically; set it for a display whose scaling the engine cannot see — a CRT, a scaler box, or a panel forcing its own aspect

This rolls up 22 commits since r21. Four of those are version bumps, issue-tracker bookkeeping, or a build-time CI fix that touches nothing compiled into the engine, and are omitted above.

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To turn it off**, launch with `-vanillaprogs`. The engine then ignores its own
  copy and uses whatever your Hexen II install provides. Nothing is deleted, so it
  is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it in `~/.hexen2/<gamedir>/` on Linux, which outranks the bundled copy.
  Windows has no user directory, so replace the files in `gamecode/` beside
  `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

One thing to know:

- **"Vanilla" now means two different things.** A build running our gamecode will
  behave differently from Raven's in ways that are not engine bugs. If you report
  a problem, please paste the `Gamecode:` line, or say whether `-vanillaprogs`
  changes what you see — that is the fastest way to tell whose bug it is, and it
  deletes nothing. This cuts both ways — some reports against older releases will
  have been gamecode issues we had already fixed.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.

**Requirements:** OpenGL 4.3 capable GPU (2012+)
