Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out.

The browser build is not one of the assets below — it deploys automatically to GitHub Pages once this release's branch lands on `master`. It will be playable at https://hexenwail.github.io/hexenwail/, installable and offline-capable after your first import; bring your own legally-owned Hexen II data, nothing is bundled.

### Changes from [0.8.0-beta.r11](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r11)

This release — **"Downstreamer"** — re-upstreams the web platform work from [alextnewman/hexenwail](https://github.com/alextnewman/hexenwail): the browser build is now a full installable PWA, offered in two renderer configurations — the modern WebGL2 pipeline (default) and the restored classic 8bpp software rasterizer, kept alive for archival. Each fork commit was reviewed and re-applied against this tree's diverged renderer and CI rather than merged wholesale; credit to @alextnewman throughout.

- Added an installable Progressive Web App shell for the browser build: an offline-capable service worker, drag-in or ZIP import of your own game data, and saves/config that sync into browser storage and survive a reload
- Added portable save bundles — export every recognized save slot as a checksum-verified ZIP from the launcher's "Saves & Backup" card and import it back on another device or browser, in merge or replace mode
- Added phone-mode touch controls (virtual stick, look region, Atk/Jump/Use/weapon buttons) for touch-only browsers, with a layout that hides the launcher chrome and gives the canvas the full viewport while playing
- Added an iOS PWA lifecycle: startup now waits for an explicit Launch press, Exit returns to the launcher instead of restarting, and shell updates are checked when the app is resumed rather than only when it's loaded, so an installed iPhone/iPad PWA can actually pick up a new version
- Added a Runtime log to the launcher and fixed the WASM startup arguments — `-basedir` was being built but never actually reached the engine, so every browser launch silently fell back to `.` as its data directory regardless of what you'd imported
- Added WebGL2 capability probing and diagnostics (`renderer_status`, `renderer_safe` console commands) with a strict CI smoke gate that compiles the engine's real shaders through software WebGL2 on every PR
  + Split the launcher's startup self-test into a structural failure (no WebGL2, a shader that won't link — blocks Start) and a quality warning (a driver's harmless pixel-rounding difference — logs and starts anyway), so a rendering difference no longer permanently disabled the Start button
  + Hid the anisotropic filtering and HDR rows in the Options menu on a browser context that doesn't support them, and fixed the menu cursor landing one row above the item it actually controlled once a row could be hidden
- Restored the classic 8bpp software rasterizer as a web build option (`WEB_RENDERER=software`, alongside the default `webgl2`) — 28 of its 29 source files are still byte-for-byte the code Hexen II shipped with in 1997 (deleted from this tree during the GL 4.3 modernization), presented through a WebGL2 palette-LUT blit so it still runs in a browser
- Fixed the software renderer's HUD and menus rendering pinned in the top-left corner instead of at their proper canvas position
- Added a dual-config WebAssembly build (`webgl2` and `software`) to CI on every pull request so the opt-in software renderer can't silently rot, and fixed an Emscripten SDL3 header lookup that could pull in a build host's native SDL3 headers instead of the port's
- Fixed browser saves and `config.cfg` not surviving a reload — the engine was writing them to a scratch directory the PWA doesn't sync, so anything changed in Options was gone the moment the tab closed
- Fixed the browser build losing all its default key bindings on a fresh install — importing only the game paks (no loose `hexen.rc`) skipped the entire startup script chain, so movement, weapon and menu keys were never bound
- Added `gl_waterwarp_speed` and `gl_waterwarp_amount` cvars (both default: 0.5) to slow down and soften the liquid surface warp, plus a Liquid Warp slider in the rendering submenu, shown as a percentage of the vanilla throw
- Fixed alias models with cutout holes in their skin (`EF_HOLEY`, e.g. grates) discarding a different set of texels than the equivalent brush geometry — reverted a threshold change that had been chasing a symptom whose real cause, the skybox leaking its alpha-cutout state onto the next entity, was already fixed elsewhere
- Fixed distant, densely-packed geometry sparkling under `gl_texturemode GL_NEAREST` — that mode had no mipmap component, so a minified texture point-sampled a single texel per screen pixel instead of blending
- Fixed white fringing on the edges of cutout textures (fences, foliage) — the alpha-bleed pass that fills transparent texels with nearby colour only ever reached one texel deep, leaving the palette's transparent-index white to bleed into the mip levels sampled at a distance
- Improved performance with `r_shadows` enabled by caching the alias light trace instead of re-walking the world BSP twice per model per frame (ported from Ironwail)
- Added a log line naming which external file replaced a texture and its dimensions, so a broken or mismatched replacement pack is visible in the console instead of indistinguishable from a renderer bug

This rolls up 27 commits since August 18. About 7 of those were issue-tracker bookkeeping, documentation, or pure internal refactors with no user-visible effect and are omitted above.

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To turn it off**, launch with `-vanillaprogs`. The engine then ignores its own
  copy and uses whatever your Hexen II install provides. Nothing is deleted, so it
  is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it in `~/.hexen2/<gamedir>/` on Linux, which outranks the bundled copy.
  Windows has no user directory, so replace the files in `gamecode/` beside
  `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.
