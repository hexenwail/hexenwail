Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out.

### Changes from [0.8.0-beta.r16](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r16)

A mod-compatibility release. Everything below came from one round of testing by BloodShot on r16, plus one feature request from him.

- Fixed a view the gamecode is holding still — a death cam, a scripted camera, a mod's custom menu — drifting under the mouse instead of staying put. The engine samples mouse, gamepad and gyro every rendered frame, but the instruction to pin the view only arrives when the server sends, so on the frames in between there was nothing to overrule the input. A pinned view now survives those frames. Added `cl_fixangle_hold` cvar (default: 0.06 seconds, 0 to disable) for gamecode that re-pins on a slower cadence than usual
- Fixed replacement model skins drawing inside out — solid where the artist painted them clear, and clear where they should be solid. Models flagged for the engine's particle-table translucency carry an inverted alpha convention that the renderer deliberately compensates for, and that compensation was being applied to replacement `.tga` and `.png` skins, whose alpha runs the other way. Models under the other two transparency flags were never affected, which is what made it findable
- Fixed `r_texture_external` doing nothing at all. It read `0` and its name promised exactly the HD-replacement-texture feature people ask about, so anyone whose texture pack was not appearing would find it, believe they had found the cause, set it, and be no better off. Replacement textures were in fact always on. The cvar now genuinely controls them and defaults to `1`, so nothing changes unless you want an off switch
  - ❗ If you set `r_texture_external 1` on a previous build to make a pack work, it was not doing anything. The pack was working for other reasons, or not working for other reasons
- Added `v_gunkick` cvar (default: `2`), ported from Ironwail with its name, modes and defaults unchanged so configs from other engines carry over:
  - **0** — no weapon kick
  - **1** — the original kick, added to the view as-is
  - **2** — the same kick blended over 0.1s. Punchangle reaches the client as whole degrees, so the original steps the view in visible integer jumps; this is what smooths them out
  - Aim is unaffected in every mode, including `0`. This changes the view only, never the shot

❗ **Note**: `v_gunkick` and the transparency fix have not been looked at across Hexen II's full spread of content. Hexen II kicks the view for spells and artifacts, not only weapons, and has three separate model transparency flags. If something looks wrong, say so — that is more useful than assuming it is intended.

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To turn it off**, launch with `-vanillaprogs`. The engine then ignores its own
  copy and uses whatever your Hexen II install provides. Nothing is deleted, so it
  is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it in `~/.hexen2/<gamedir>/` on Linux, which outranks the bundled copy.
  Windows has no user directory, so replace the files in `gamecode/` beside
  `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

Two things to know:

- **"Vanilla" now means two different things.** A build running our gamecode will
  behave differently from Raven's in ways that are not engine bugs. If you report
  a problem, please paste the `Gamecode:` line, or say whether `-vanillaprogs`
  changes what you see — that is the fastest way to tell whose bug it is, and it
  deletes nothing. This cuts both ways — some reports against older releases will
  have been gamecode issues we had already fixed.
- **Portals: the Crusader's Glyph of the Ancients damages you too.** The glyph
  detonates on whoever touches it for real damage — 50 in deathmatch, 37
  otherwise — the caster included. Do not walk into your own glyph. This is
  Raven's original behaviour, so nothing changes if you are coming from a stock
  `progs.dat`; it is called out because Hexenwail's own gamecode briefly let the
  glyph pass harmlessly through the caster, and that exemption is gone.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.
