Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out. This release adds a `Gamecode loaded:` row to Options > Game reporting whose gamecode is actually in effect, plus a dated build stamp on the console's `Gamecode:` line, so a bug report can name the exact revision without anyone needing to compare CRCs by hand.

### Changes from [0.8.0-beta.r2](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r2)

- Added `r_softparticles` (default: 0), which fades a sprite's alpha as it nears the opaque geometry behind it instead of slicing it off along a hard rectangular edge — visible on explosion and smoke billboards that intersect a wall or floor. `r_softparticles_scale` (default: 8) sets the fade distance in world units. Exposed as "Soft Sprites" under Options > Rendering
- Fixed order-independent transparency (`r_oit 1`) rendering no translucent sprites or particles at all — the resolve pass's fullscreen triangle was itself front-face culled, so the correctly-filled accumulation and revealage buffers were composited nowhere. This is the same bug behind two previously closed reports that blamed a Mesa Intel Iris Xe driver quirk; it reproduces identically under software rendering, so the driver was never at fault. Two more fixes landed alongside it:
  + Restored the scene viewport after the resolve pass, which had been left at full-buffer size and was drawing glows, the view model and the mirror through the wrong transform — visible as the mana orb glows sitting about 24px below the orbs they belong to
  + Stopped forcing an archived `r_oit 1` back to 0 on every launch, which had been hiding the fact that the feature previously did nothing (default stays 0)
- Fixed `vid_config_fsaa` (antialiasing) being reset to 0 and rewritten into `config.cfg` on every mode change, so a non-zero MSAA setting could never survive past the launch that set it. This also made the multisampled OIT resolve path reachable in practice for the first time
- Fixed the selected inventory artifact resetting to the torch on every level change, and made the selection survive a save and reload too — previously only a `load` issued in the same session kept it, so quitting and relaunching, or loading an older save mid-campaign, still lost the selection. Requested on Discord by 'Tome of Power Abuser'; reported again by Mathuzzz
- Improved gamecode identification, so a report can say whose code produced a bug without needing the whole-file CRC:
  + Added a read-only `Gamecode loaded:` row to Options > Game, naming the gamecode actually in effect — Raven's retail, Hexenwail's own, or third-party — independent of the Classic/Updated toggle. A `progs.dat` hand-copied into `data1/` previously read as "Classic" in the menu while silently running our fixes
  + The console's `Gamecode:` line now carries a build date, e.g. `hexenwail-2026-08-15`, instead of only the fork name
- Added tab completion for `exec`, `save`, `load` and `sky` in the console — configs, save directories and skybox names, joining the `map`, mod and demo name completion already there
- Fixed `vid.fullbright` being computed from a read that ran three bytes past the loaded colormap — undefined behavior that happened to compute the right answer (255, meaning Hexen II has no usable fullbright range) by accident. It now reads a single validated byte, and the colormap's length is checked at load, so a mod shipping a short custom colormap is caught instead of over-read by every consumer that walks its 64 lighting rows
- Fixed a `.lit` colored-lighting file whose size doesn't match the map it claims to light being loaded anyway, reading past the end of a short file and applying an unrelated compile's lighting to every surface — most visibly turning alias model skins a flat solid color, since alias lighting samples the lightmap almost directly rather than modulating a texture. A mismatched `.lit` is now rejected with a console message naming the expected and actual size, and the map falls back to its own lightmap
- Fixed the Mods menu listing mods from beside the launch directory instead of `-basedir`'s target when `-basedir` was in use, so the menu and the `game` console command disagreed about which mods existed — the Mods menu would list a mod and then refuse to load it. Fixed the bundled soundfont search missing a soundfont shipped with the game data under the same `-basedir` mismatch
- Added a load-time warning when a savegame's stored entity fields don't fit the loaded gamecode, e.g. `WARNING: 7 saved fields could not be restored.`, instead of silently dropping that state with no summary. The load still isn't blocked — you're just no longer left to notice the missing state on your own
- Documented, for content authors, that a replacement `.mdl` model also resizes its entity's collision box (±10 units per axis around the mesh) if the entity's own logic never calls `setsize()` — existing, unchanged behavior that wasn't written down anywhere before now (`docs/SrcNotes.txt`)
