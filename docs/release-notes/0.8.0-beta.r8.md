Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out.

### Changes from [0.8.0-beta.r7](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r7)

- Fixed the entire world (and its skybox) vanishing on large maps: far-clip culling tested each world node's bounding box by its *centre* against `r_farclip`, which is not conservative — a node whose geometry reached much closer to the camera than its centre was culled anyway, and on a big enough map that node was the root, taking the whole world, sky depth and stencil with it
- Added HD texture replacement pack support, closing a feature gap Garrett asked about on Discord (jsHexen2 and FTEQW both already do this):
  + Fixed external texture replacements silently losing their fullbright glow layer — the glow mask used to be derived from the *embedded* texture's palette indices, which an RGBA replacement doesn't have, so installing any HD pack put out every torch, rune and monster eye in the game. Replacements now take their glow from a companion `<name>_glow` or `<name>_luma` file, so packs already built for FTE or jsHexen2 work unmodified
  + Added a per-map texture override directory (`textures/<mapname>/<texname>`, searched before the shared `textures/` pool), so two maps no longer have to agree on what `wall01` looks like
  + Added DDS and KTX loading (DXT1/3/5, ATI1/ATI2, BC1–BC5/BC7, KTX 1.1) so compressed replacement textures upload compressed instead of being inflated to raw RGBA on the CPU first — about 3 MB of VRAM instead of ~21 MB for a 2048² texture
- Fixed monsters, items and other alias models glowing with the fog color instead of fading to black when seen through fog on an additive fullbright pass (torches, eyes, and similar glow effects) — visible on every fogged map at the default `r_alias_gpu 1`, since the same bug also fed the instanced pass an unscaled fog density that saturated to zero almost immediately
- Fixed instanced (GPU-batched) shadows all projecting from whichever entity happened to be collected last, instead of each entity's own floor height and light direction — shadows for a whole batch of models would sit at the wrong height, floating or sinking relative to their owner
- Fixed a one-frame animation pop on every pose change with `r_lerpmodels 1` on the non-instanced (legacy) alias path — the new pose flashed in at full weight for a frame before lerping backward from it, most visible on the view model and on translucent or colormapped entities
- Fixed a translucent brush entity containing a sky face discarding the rest of its own faces for the remainder of the frame — the sky shader borrows the alpha-threshold uniform as a two-layer/single-texture mode switch, and nothing restored it after a sky draw, so whatever drew next inherited a threshold of 1.0
- Fixed a map with more than one `sky*` texture leaving a hole in the world — no geometry, no depth, no stencil, and so no skybox behind it either — wherever the second sky texture's faces were, because only the most recently loaded one was ever recognized as sky
- Fixed post-process HDR and bloom not responding to their own toggles at runtime, requiring a resolution change or `vid_restart` to take effect:
  + `r_bloom` (default: 0) was a silent no-op whenever MSAA was enabled (`vid_config_fsaa` ≥ 2), because the MSAA success path skipped building the bloom pyramid entirely
  + Toggling `r_hdr` (default: 0) mid-session kept rendering into a clamped 8-bit buffer instead of switching formats, so the ACES tonemap was compressing an image that was already clipped
  + Toggling `r_bloom` never allocated or freed its FBO pyramid on its own
- Fixed loading any `.md5mesh` model corrupting the cache-memory heap — the loader stored a hunk-allocated header where the cache system expected its own bookkeeping bytes to sit immediately before the pointer, splicing garbage into the cache's LRU chain on the model's first access
- Fixed BSP V29 maps with more than 32,768 marksurfaces reading and writing out of bounds at load time, because the leaf and node loaders counted them as signed 16-bit values that wrapped negative past that point
- Fixed world, fence/underwater and sky surfaces silently vanishing on a sufficiently complex view instead of being drawn, once a single texture chain's fixed-size batch (4096–8192 entries depending on which one) filled up — the sky case additionally left those pixels with no depth or stencil write, so the skybox would bleed through the walls behind them
- Fixed a brush submodel's sky, water and fence surfaces occasionally being drawn (or re-drawn) by the wrong frame's render pass, including two entities sharing the same submodel bleeding each other's draw marks, by giving each pass its own id instead of reusing a field that backface culling could leave stale
- Fixed the deferred fence/underwater batch and water surfaces occasionally drawing with whatever texture happened to already be bound, because that bind path skipped the engine's texture-bind cache instead of keeping it in sync
- Fixed entities with a colorshade tint rendering a different color depending on how they were dispatched — translucent, colormapped, high-numbered-skin and `r_alias_gpu 0` entities ignored their tint entirely, while GPU-instanced ones applied it, so the same entity could look two different colors from one draw call to the next
- Fixed the water surface ripple collapsing into flat 1-D stripes, and sometimes disappearing outright, because its second axis was built from the surface's constant height rather than its horizontal position
- Fixed world surfaces flashing solid white for one draw batch right after a shader/program switch with `r_fullbright 1` and `gl_overbright 1` both set, from an immediate-mode code path re-applying the 2x overbright multiplier `r_fullbright` exists to suppress
- Fixed instanced models occasionally collapsing to a single point for one frame after a shadow-pass teardown, when a raw buffer bind bypassed the binding cache and a later frame reused a stale, incorrect cache hit
- Fixed rain from a brush suspended well above the floor stopping dead in mid-air instead of falling the rest of the way down — clearest on Portals of Praevus' `demo1`, where the rain volume's bottom sits 587 units above a player start and the rain used to end as a band overhead that never reached the ground
- Fixed `r_raincollide` (default: 1) silently deleting rain drops that spawn inside solid geometry instead of retrying the spawn point — measured across every stock map with rain, this was quietly deleting over half of `castle4`'s rain: ten of its seventeen rain volumes have their top plane 50–98% embedded in the map's own retail architecture. The retry recovers about 97% of that rain
- Fixed the Flatpak manifest building and bundling its own frozen copies of libogg, libvorbis and libopus instead of linking the ones `org.freedesktop.Platform` 25.08 already ships — the bundled copies were a second, unmaintained set shadowing the runtime's, and a Flathub review finding in their own right
- Documented the WASM/WebGL2 build and the planned Android target in the README's platform support tables
- Removed the `GL_LUMINANCE` lightmap format. It was never valid under the core GL 4.3 pipeline — the atlas upload errored and sampled black — its 1-byte store wrote inverted luxels left over from a texture-blend mode the GLSL pipeline replaced years ago, and it loaded one byte per luxel while alias-model lighting read three, past the end of the buffer. Requesting it via cvar or `-lm_1` now warns and falls back to RGBA

This rolls up 39 commits since `0.8.0-beta.r7`. About 17 of those were issue-tracker bookkeeping, documentation, or pure internal refactors and build/CI-only fixes with no user-visible effect and are omitted above.

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To turn it off**, launch with `-vanillaprogs`. The engine then ignores its own
  copy and uses whatever your Hexen II install provides. Nothing is deleted, so it
  is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it in `~/.hexen2/<gamedir>/` on Linux, which outranks the bundled copy.
  Windows has no user directory, so replace the files in `gamecode/` beside
  `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

Two things to know:

- **"Vanilla" now means two different things.** A build running our gamecode will
  behave differently from Raven's in ways that are not engine bugs. If you report
  a problem, please paste the `Gamecode:` line, or say whether `-vanillaprogs`
  changes what you see — that is the fastest way to tell whose bug it is, and it
  deletes nothing. This cuts both ways — some reports against older releases will
  have been gamecode issues we had already fixed.
- **Portals: the Crusader's Glyph of the Ancients damages you too.** The glyph
  detonates on whoever touches it for real damage — 50 in deathmatch, 37
  otherwise — the caster included. Do not walk into your own glyph. This is
  Raven's original behaviour, so nothing changes if you are coming from a stock
  `progs.dat`; it is called out because Hexenwail's own gamecode briefly let the
  glyph pass harmlessly through the caster, and that exemption is gone.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.

**Requirements:** OpenGL 4.3 capable GPU (2012+)
