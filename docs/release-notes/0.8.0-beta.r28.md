Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out.

### Changes from [0.8.0-beta.r27](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r27)

**Movement and physics**

- Fixed `sv_physfps` being archived into `config.cfg`, where a value set once — for a benchmark, by a mod, at the console an hour ago — silently changed how the game played on every launch afterwards, permanently. Air acceleration counts ticks rather than seconds (`SV_AirAccelerate` gains at most `addspeed` per tick, a figure that does not scale with `frametime`), so the tick rate is a gameplay setting wearing a performance setting's clothes. It is session-scoped now, like `map_checks` and `sv_protocol`
  + The stock defaults reproduce r6303's movement exactly, and that is checked rather than asserted: `sv_user.c` is r6303's file verbatim bar one console-command name, every movement and physics cvar matches r6303's default *and* its flags, and 72 Hz is r6303's own rate — it runs one server frame per rendered frame at the real frametime, capped by `host_maxfps`, whose default is also 72
  + Both escape hatches in `docs/MODDING_TICKRATE.md` still work. A mod's own `.cfg` and `cvar_set()` each set the tick for as long as that mod is loaded; neither can follow the player back to the base game
  + Changing it now prints a note, so a non-stock tick is visible on screen instead of buried in a file
- Fixed analog stick movement scaling with the frame rate. Input is sampled once per rendered frame but consumed once per physics tick, and the stick's deflection — a speed, not a distance — was being summed across those frames, multiplying commanded movement by `render_fps / sv_physfps`. Invisible at the matched 72/72 defaults; raise the FPS cap and walking speed rose with it. The mouse was never affected, because a mouse reports a delta and summing deltas is right
  + Also fixes the mirror-image case: when the renderer runs *slower* than the tick, one frame feeds several ticks, and every tick after the first used to see a stick snapped back to centre

**Lighting and the renderer**

- Added clustered GPU dynamic lighting. A froxel grid is built by a compute pass each frame and both world surfaces and alias models take dynamic light **per pixel** from it, so a light near a large face lights the part of the face it reaches instead of the whole polygon
  + Added `r_lightclusters` (default: 1) and `r_lightclusters_models` (default: 1)
- Added a cubemap skybox path, so the wind no longer tears at the seams between skybox faces. The sky shader is split into Ironwail's specialised programs rather than one branching über-shader. Added `r_skycubemap` (default: 1)
- Added lit water — liquid surfaces keep their lightmap instead of being drawn fullbright. Added `r_litwater` (default: 1)
- Decomposed `r_softemu` into Ironwail's per-stage cvars, so the software-renderer look can be assembled a piece at a time rather than taken whole: `r_softemu_dither_screen`, `r_softemu_dither_texture`, `r_softemu_lightmap_banding`, `r_softemu_mdl_warp` (affine texture mapping on models, the wobble that gives the original its character), and `r_softemu_metric`, which picks how the GPU palette LUT chooses its nearest colour
- Added `vid_fsaamode` (default: 0) — per-sample shading, which this engine had nowhere before
- Added `r_particles` as an adapter for the particle toggle upstream conflates with particle *style*

**Models**

- Added a real MD3 loader. `.md3` files load as models in their own right, with frame interpolation
- Added `r_enhancedmodels` (default: 1) and `r_enhancedmodels_priority` (default: `md3,md5`), substituting an `.md3` or `.md5mesh` sibling for a `.mdl` when one is present. A replacement is only accepted from the `.mdl`'s own gamedir or a later one, so a base-game replacement can never override a mod's own model
- Fixed a missing precached model killing the engine. It draws as a checkerboard placeholder now and the map keeps running, which is the difference between a diagnosable report and a crash log

**Menus and UI**

- Added a maps browser (`menu_maps`) — Ironwail's ExtraMaps, listing the maps your install can actually load, with a search filter
- Ported Ironwail's `ui_*` menu interaction cvars, with Game Options rows for **Live Preview** (`ui_live_preview`) and **Mouse Sounds** (`ui_mouse_sound`)
- Added `scr_menubgalpha` (default: 1), controlling how far the world dims behind an overlay
- Added `vid_test`, which applies a video mode and reverts it on a timeout unless you confirm — the point being that a mode you cannot see is a mode you cannot back out of
- Added a Demo Bar row for `scr_demobar_timeout`
- Fixed `bindlist.lst` offering rows for actions this engine cannot perform

**Video modes**

- Added the Quake-lineage spellings of the video cvars this engine already had: `vid_width`, `vid_height`, `vid_fullscreen`, `vid_desktopfullscreen`, `vid_refreshrate` and `vid_fsaa`. Each mirrors its `vid_config_*` twin in both directions, so a shipped `autoexec.cfg`, a mod's cfg or a wiki page that says `vid_width 1280` now does something. An older config carrying only the old names still applies
- Added `vid_describemodes`, and `VID_Lock` / `vid_unlock` so a mod's `config.cfg` cannot take your resolution on a `game` switch
- Added `scr_conwidth` and `scr_conscale`, where zero on either lets the two act as one setting
- Added `scr_pixelaspect`, the 2D counterpart to `vid_pixelaspect`

**Input**

- Added `freelook` (default: 0), the always-on mouselook name every Quake-lineage engine uses. Mouselook is a cvar now rather than a `+mlook` line appended to `config.cfg`, which is what made it impossible to untick from the Options menu — a config that still carries the old line migrates itself on first run
- Added `cl_mwheelpitch` (default: 5), banking a pitch amount per wheel notch and paying it out at `cl_pitchspeed`, so a wheel bound to `+lookup` / `+lookdown` feels like the keyboard rather than a snap
- `mwheelthreshold` is read at last, seven years after it was added and archived. It banks wheel travel in `WHEEL_DELTA` units, so a precision wheel or a trackpad sending fractions of a notch behaves; a classic detented wheel is byte-identical to before
- Added `in_debugkeys` and `ui_mouse`

**Demos and the client**

- Demo playback gets speed control: space pauses, up and down halve and double the base speed between 0.25× and 8×, the right arrow fast-forwards at 5× while held, and shift or ctrl quarters whatever is in effect. Rewind is deliberately not in this — the format has no index — and the left arrow holds playback still instead
- Added `cl_startdemos` (default: 1) and `cl_titlestats` (default: 1), the latter putting the level, skill and kill/secret counts in the OS window title
- Added `devstats` (default: 0), a per-frame client resource readout with high-water marks

**Server and gamecode**

- Added autosave — `sv_autosave` (default: 1) and `sv_autosave_interval` (default: 30). It is not a timer: it scores the moment and saves when the score crosses, so it lands while you are standing still and healthy rather than mid-fight. The scoring is adapted for Hexen II's four independent armour pieces, which the literal upstream formula would have read as zero armour always
- Added `map_checks` (default: 0), mapper mode. The interesting half is not the extra warnings but the three renderer workarounds it switches **off** — `gl_zfix`, order-independent transparency and alpha sorting all exist to make coplanar or badly ordered brushwork look acceptable anyway, which is the opposite of what the person authoring it needs to see
- Added `sv_protocol` as a console command, so choosing a wire format no longer means relaunching the process — or, on a dedicated server, restarting the server
- Added the `checkextension` QuakeC builtin at #130, on both the client and server. It answers no to everything on purpose, and logs what each mod asked for, which turns "the mod does not work" into a list of what it wanted
- `external_vis` now reaches the third brush loader

**Console and cvars**

- Added `toggle`, `reset`, `resetall`, `cycle` and `inc`, and `Cvar_RegisterAlias` for the cases where the parity gap was only spelling
- Merged upstream sezero/uhexen2: libtimidity updated from mainstream, plus two `pakx` fixes — extracting directories by trailing slash, and returning a failing status code when a requested file is not found
- `entsearch` is `mapsearch` again, at Inky's request

This rolls up 83 commits since r27. Issue-tracker bookkeeping, documentation and internal build/test commits with no user-visible effect are omitted above.

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To turn it off**, launch with `-vanillaprogs`. The engine then ignores its own
  copy and uses whatever your Hexen II install provides. Nothing is deleted, so it
  is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it under `<userdir>/<gamedir>/` on Linux, which outranks the bundled copy.
  The engine prints `userdir is:` at startup if you are unsure which one you have;
  it is `~/.local/share/hexen2` on a fresh install and `~/.hexen2` if you already
  had one, and `-userdir` now overrides both. Windows has no user directory, so
  replace the files in `gamecode/` beside `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

One thing to know:

- **"Vanilla" now means two different things.** A build running our gamecode will
  behave differently from Raven's in ways that are not engine bugs. If you report
  a problem, please paste the `Gamecode:` line, or say whether `-vanillaprogs`
  changes what you see — that is the fastest way to tell whose bug it is, and it
  deletes nothing. This cuts both ways — some reports against older releases will
  have been gamecode issues we had already fixed.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.

**Requirements:** OpenGL 4.3 capable GPU (2012+)
