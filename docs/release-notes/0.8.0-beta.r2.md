Compiled Hexen II and Portals of Praevus gamecode ships in both zips and loads automatically — see **Compiled gamecode** below for what that means and how to opt out. This release adds an in-game switch for it, so `-vanillaprogs` is no longer the only way back to your install's own `progs.dat`.

### Changes from [0.8.0-beta.r1](https://github.com/hexenwail/hexenwail/releases/tag/0.8.0-beta.r1)

- Added an in-game gamecode selector under Options > Game — "Gamecode: Classic / Updated", archived to config, default Updated. It latches at map start rather than applying immediately: a savegame validates its progdefs CRC against whatever is loaded, so swapping mid-campaign would leave you unable to load your own saves. `changelevel`, `restart` and save loads deliberately do not re-latch, and `-vanillaprogs` still outranks the setting entirely
- Added `r_softemu 3`, a software-renderer emulation mode that quantizes through Raven's own `gfx/colormap.lmp` instead of by nearest RGB distance. The 1997 rasterizer never picked a color by distance — every lit pixel was a lookup into 64 hand-authored darkening ramps that bend and shift hue in the dark ranges, which a Euclidean search cannot reproduce. Modes 1 and 2 are unchanged
- Added tab completion for command arguments in the console — map, mod and demo names. Completion previously refused any partial containing a space, so `map dem<TAB>` did nothing. Completion is keyed on both the command and which argument slot the cursor sits in, so `record <demoname> [<map>]` completes maps in its second slot and not its first
- Added a `setpos` command, as in Ironwail and QuakeSpasm, cheat-gated exactly like `noclip` (single player, skill ≤ 2). Bare `setpos` prints the current position. One deliberate difference from Ironwail's: it does not force `MOVETYPE_NOCLIP`, so whatever is at the destination still fires on arrival — type `noclip` first if you want to land inside geometry
- Added `scr_infoscale` (default: 2.0), giving the showfps / showclock / showspeed readouts their own canvas and scale instead of a fixed 8×8 that was a squint at 4K. Clamps to what the window can hold rather than pushing text off the right edge
- Added the rest of Ironwail's pointfile leak helpers, which make the feature findable without already knowing it exists:
  + `pointfile leak` auto-loads on a map whose world has no visdata — usually because qbsp found a leak and stopped — and stays silent when there is no `.pts` file, so a leaked map does not nag on every load
  + a console warning when a leak is confirmed, and a "Leak" label drawn in the world at the path origin
- Made `r_fullbright` and `r_lightmap` actually affect world surfaces. Both were inert on brush geometry — `r_fullbright` only ever gated the alias-model re-draw, and `r_lightmap` was registered and never read. That is worse than a missing feature: the switches answered, they just answered with the unmodified frame, so any lighting test built on them returned "no change" and read as evidence
- Made `gl_farclip` (default: 16384) control the projection far plane. It was registered at 2048 purely so ported Ironwail sky code had the name to compile against; nothing read it, while the frustum used a hardcoded value. It is the name Ironwail and QuakeSpasm both use for this setting, so a tester following upstream docs would set it, see it accepted, and rule the far plane out. Now archived and clamped to [4096, 262144]
- Fixed the Necromancer's magic missile drawing as a black square. `models/ball.mdl` ships from `pak0.pak` with no transparency flag, unlike the three other billboards built the same way, so its index-0 background rendered opaque. Raven caught this themselves — the copy in Portals of Praevus is flagged correctly, which is why the black box only appeared on base-game installs. The flag is now added at load time, and only when the loaded copy declares no transparency mode, so a mod shipping its own `ball.mdl` is left alone
- Fixed the bicubic lightmap filter sampling outside each surface's lightmap rect, drawing bright and dark seams along surface boundaries. The half-luxel inset it inherited is sized for bilinear's ±0.5-texel footprint; bicubic's 4×4 support reaches one luxel before the rect and two past it, into an unrelated surface — or, at a page edge, an unrelated atlas page. Every rect now carries a gutter that is edge-extended on each rebuild
- Fixed constant lightmap flicker introduced by that gutter fill, which walked rows by a stride that had already had the surface width subtracted from it and so wrote one surface's edge luxels across other surfaces' light, on every frame with dynamic lights
- Fixed every brush entity in the map — doors, platforms, buttons, `func_wall`, `func_illusionary` — rendering as holes you looked straight through on the GL ES / WebGL tier. The instanced brush path advertised itself as available there, but its entire body is compiled out on a tier with no SSBOs, so it claimed the work and did nothing while the legacy fallback was skipped
- Fixed a run of GL ES 3.0 / WebGL2 failures that had never been reachable outside a browser build. The tier is now selectable at build time (`USE_GLES`) instead of being keyed on Emscripten, which is how these were found:
  + 55 texture uploads failed on every map load — blacking out the status bar, conback, sky and liquid warps — because opaque textures asked for `GL_RGB8`, which ES 3.0 rejects against the `GL_RGBA` data actually handed to it
  + the post-process chain (gamma, contrast, FXAA, motion blur, tonemap, bloom, palettization) emitted desktop `#version 430 core` headers and could not compile
  + the OIT programs died on a precision declaration spliced into the wrong place, and are no longer built on a tier that cannot select them
  + the GPU particle buffer allocated a shader storage buffer, which is not a valid target there, costing two GL errors and 1 MB of the WASM module's linear memory for something nothing could reach
  + screenshots read back as `GL_RGB`, a desktop spelling ES 3.0 does not promise
  + none of the above printed anything, because `KHR_debug` does not exist on that tier; the engine now polls `glGetError` instead
- Fixed `game data1` leaving Portals of Praevus on the search path for the rest of the session. A `-game` launch folds the mission pack into the base path so mods can read its assets, and the unwind stopped short of that — so the command renamed the gamedir and changed nothing about what the engine read. Base-game maps ran on portals maps, models, sounds, configs and `progs.dat`
- Fixed runtime mod switching being impossible under `-basedir`. The switch validated the target against the startup working directory while the filesystem lived under `-basedir`, so it refused every mod with `Game directory "<name>" not found` — including from the Mods menu, which would list mods and then decline to load any of them. Anyone launching through a shortcut, launcher or wrapper that passes `-basedir` had a Mods menu that could not work
- Fixed the engine re-adding `portals/` immediately after validating it and rejecting it, and fixed it continuing to report itself as running the mission pack after that rollback
- Fixed the texture manager only ever growing. A texture reloaded with different dimensions or flags retired its old slot and allocated a new one, and nothing ever reclaimed the retired slot, so the count climbed toward the hard 8192 limit and its `Sys_Error`
- Fixed alias skins staying opaque when a map's `misc_modelpimp` grants `EF_HOLEY` at runtime — the draw path took the cutout branch while every texel was still fully opaque, so nothing was ever discarded. That is the solid black background behind Storm Over Thyrion's castle torches. Skins are re-uploaded with alpha when the flag is newly added; models that already declare it in their header are untouched
- Fixed long mod-supplied `bindlist.lst` labels running through the key names in Key Setup. Labels are shortened with an ellipsis at draw time only; the modder's full string is still stored
- Reverted the mipmap filter demotion applied to cutout textures in 0.7.8-beta.r29. It was added for a theory since ruled out, it could not have done what it claimed (nearest-mip selection still samples bilinearly within the chosen mip), and it survived only until the first time the player touched `gl_texturemode`, after which uploads and filter changes disagreed for the rest of the session
- Fixed forged or corrupt bytecode in a `progs.dat` / `csprogs.dat` being executed unchecked. Instruction operands index the globals array raw, and the write operand made a bad one an arbitrary write; the dispatch loop had no bound against the statement count, so a body that never returned walked off the lump and executed whatever followed it in the hunk. Both are reachable from a player-supplied `csprogs.dat` that arrives with downloaded mod or server content. Bytecode is now validated once at load, leaving the interpreter's hot loop untouched
- Fixed a crash on a `csprogs.dat` whose function-name offsets point outside the string pool, plus several short-read and console-copy bugs found alongside it
- Fixed the status bar disagreeing with itself on a data1-only install with `cl_playerclass 5` set at the console: the armor class was read out of the Demoness column while the name beside it fell back to and printed "Paladin". The two halves apply the same guard to the same cvar from a 0-based and a 1-based index, and only one of them was right. The fallback itself was also wrong — both sides said "default to Paladin" and the 0-based one assigned the Crusader
- Fixed, in the bundled gamecode, henchmen passing the drop roll and then dropping nothing on roughly 1.5% of kills. Raven's drop table ends one branch early, leaving the top 10% of the roll assigned to no item at all; confirmed present in retail `PROGS.DAT`, and in our build because ours is a faithful build of the same source
- Fixed, in the bundled Portals gamecode, monster loot being rolled onto the corpse instead of the backpack about to carry it, and a stale local making the game report an artifact it had never rolled. Both ended in the same "Bad backpack!" dead end
- Fixed the dedicated server being unable to load Storm Over Thyrion at all — the `pimpmodel` builtin was unimplemented server-side, so the first call raised a program error
- Fixed the dedicated server spinning on a stdin that is at EOF — redirected from `/dev/null`, a consumed file, or a closed pipe — which printed one "Console input too long!" per frame and drowned the log
- Fixed `Sys_GetExeDir` returning nothing on macOS, so everything layered on it (bundled gamecode, the soundfont search) silently had one fewer place to look
- Fixed the Nix/Flatpak install path shipping without the gamecode, and made tester builds carry the release's gamecode too

This rolls up 66 commits since `0.8.0-beta.r1`. About 28 of those were issue-tracker bookkeeping, documentation, build plumbing or pure internal refactors with no user-visible effect and are omitted above.

### Downloads

- **Linux x86_64** — extract and run `glhexen2` from your Hexen II data directory
- **Linux Flatpak** — `flatpak install hexenwail-*.flatpak`, then place game data in `~/.var/app/io.github.hexenwail.hexenwail/.hexen2/data1/`
- **Windows x86_64** — extract anywhere, drop `pak0.pak`/`pak1.pak` into the included `data1/` folder, run `glh2.exe`

Requires game data files (`data1/pak0.pak`, `data1/pak1.pak`).

### Compiled gamecode — included, and already in use

Both zips carry the Hexen II game logic rebuilt from source, with fixes that are
not in Raven's 1997 `progs.dat` (chiefly dropped backpacks silently vanishing in
co-op and deathmatch).

**There is nothing to install.** The engine ships its own copy beside the
executable and prefers it to the one in your Hexen II folder — on Linux and on
Windows alike, straight out of the zip. Nothing is copied and nothing of yours is
overwritten.

- **To see which gamecode you are running**, look for the `Gamecode:` line the
  engine prints when it loads one. It names the exact file and its checksum.
- **To switch back to your install's own**, set Options > Game > "Gamecode" to
  Classic. It takes effect on the next new game, not mid-campaign — your saves
  are tied to the gamecode that made them.
- **To take it out of the picture entirely**, launch with `-vanillaprogs`. That
  outranks the menu setting. Nothing is deleted, so it is a per-launch decision.
- **To run different gamecode** — a translation, a balance patch, your own build —
  put it in `~/.hexen2/<gamedir>/` on Linux, which outranks the bundled copy.
  Windows has no user directory, so replace the files in `gamecode/` beside
  `glh2.exe` instead.

The `gamecode/` folder in the zip is those same three files. On Windows it *is*
the copy the engine loads, since it sits next to `glh2.exe`; on Linux the engine
loads its own from the platform directory and this one is a spare you can install
by hand into a different engine. See `gamecode/README.txt`.

Two things to know:

- **"Vanilla" now means two different things.** A build running our gamecode will
  behave differently from Raven's in ways that are not engine bugs. If you report
  a problem, please paste the `Gamecode:` line, or say whether Classic changes
  what you see — that is the fastest way to tell whose bug it is, and it deletes
  nothing. This cuts both ways — some reports against older releases will have
  been gamecode issues we had already fixed.
- **Portals: the Crusader's Glyph of the Ancients damages you too.** The glyph
  detonates on whoever touches it for real damage — 50 in deathmatch, 37
  otherwise — the caster included. Do not walk into your own glyph. This is
  Raven's original behaviour, so nothing changes if you are coming from a stock
  `progs.dat`; it is called out because Hexenwail's own gamecode briefly let the
  glyph pass harmlessly through the caster, and that exemption is gone.

### Reporting a crash

Windows builds report crashes by themselves — there is nothing to install or enable.
If the game dies, a file called `glh2.RPT` appears next to `glh2.exe`.
Attach that file and `qconsole.log` from the same folder to your report.

The Windows build ships with debug symbols, so that report names the source file
and line the game died on — there is no separate debug download to fetch.

To verify a download, fetch `SHA256SUMS` alongside it and run `sha256sum -c SHA256SUMS`.
